## 2026-08-03 - Secure Password Reset Token Storage & JWT Cookie Protection
**Vulnerability:** The application was storing password reset tokens in plaintext within the MongoDB database. If the database was compromised, an attacker could retrieve valid tokens and hijack accounts without authorization. Additionally, authentication JWT cookies were configured with `secure: false` even in production, risking transmission over unencrypted channels.
**Learning:** Storing authentication or recovery tokens in plaintext violates the principle of "defense in depth". Tokens should always be treated similarly to passwords (hashed or signed). Cookie security attributes should also be dynamic based on the environment to ensure HTTPS-only transmission.
**Prevention:** Always hash password reset/recovery tokens using SHA-256 (or similar cryptographic hashing algorithm) before database storage, and dynamically set `secure: config.nodeEnv === "production"` for authentication cookies to protect transmission in production environments.
