## 2026-08-13 - Password Reset Token Storage and Secure Session Transmission
**Vulnerability:** Cleartext storage of password reset tokens in MongoDB and insecure cookie transmission over unencrypted HTTP connections.
**Learning:** Raw password reset tokens were generated using crypto random bytes and stored directly as plaintext in MongoDB. If the user collection was leaked or compromised, active tokens could be abused immediately to hijack user accounts. Additionally, session cookies were set with `secure: false` unconditionally, exposing JWT tokens to interception on public networks in production behind SSL-terminating proxies (like Cloudflare/Railway).
**Prevention:** Always store sensitive, short-lived tokens as SHA-256 hashes inside the database while transmitting the cleartext counterpart solely via the communication channel (e.g. email, reset URL). Query for the token by hashing the incoming request value and performing the database lookup with the hashed token. Bind cookie transport security directly to the application environment state using `secure: process.env.NODE_ENV === "production"`.
