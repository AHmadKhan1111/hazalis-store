## 2026-07-28 - Secure Password Reset Token Storage and Cookie Security
**Vulnerability:** Plaintext password reset tokens were stored directly in the database. If the database is compromised, an attacker can access these plaintext tokens and bypass authorization checks or take over user accounts. Additionally, session cookies had the `secure` flag explicitly hardcoded to `false`, allowing session data transmission over unencrypted connections.
**Learning:** This occurred due to prioritizing convenience in development environments and not separating development config from production. Storing tokens directly in database queries without hashing is a common design gap.
**Prevention:** Always hash sensitive short-lived tokens (like reset password tokens, API keys, or verification codes) using a secure cryptographic hashing algorithm (such as SHA-256) before database storage. Set session cookie attributes (such as `secure`) dynamically based on the current environment configuration (`process.env.NODE_ENV === "production"`).
